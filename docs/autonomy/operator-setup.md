# Einrichtung durch den Operator (einmalig)

Danach baut eine Lead-Sitzung in der Claude-Cloud bis zum veröffentlichten Release v0.1.0, ohne dass du etwas tun musst. Reihenfolge einhalten; Schritt 1 muss vor dem Merge in Schritt 4 erledigt sein.

1. **Bypass im Ruleset 25426278 eintragen, bevor der Bootstrap-PR gemergt wird.** GitHub → Repository `ahlerjam/academic-research` → Settings → Rules → Rulesets → Ruleset 25426278 → Abschnitt „Bypass list" → **Add bypass** → Rolle „Repository admin" suchen, auswählen, **Add Selected** → im Menü (⋯) rechts neben „Always allow" **For pull requests only** wählen → speichern. Ohne diesen Eintrag sperrt dich `protect` nach dem Bootstrap selbst aus, weil es Kernpfade für jeden Autor rot meldet. Required Checks bleiben `gate` und `protect`.
2. **Auto-Merge erlauben.** Settings → General → Abschnitt „Pull Requests" → **Allow auto-merge** anhaken. Die Lead-Sitzung schaltet Auto-Merge je PR ein; GitHub merged erst, wenn `gate` und `protect` grün sind.
3. **Cloud-Umgebung `academic-research` anlegen.** claude.ai/code → im Startbildschirm das erste Bedienelement unter dem Eingabefeld (Umgebungsauswahl) → **New environment**:
   - Name: `academic-research`.
   - Network access: **Custom** mit genau diesen Hosts: `nodejs.org`, `registry.npmjs.org`, `github.com`, `api.github.com`, `objects.githubusercontent.com`, dazu den Haken „Also include default list of common package managers". Grund: In der Umgebung laufen Agenten, die fremden PDF-, Web- und Issue-Text lesen; mit vollem Netz könnte ein per Prompt-Injection gesteuerter Agent Daten an beliebige Hosts schicken. Was fehlt, zeigt sich als `403 host_not_allowed`: Die Lead-Sitzung meldet den Host als `op:external`-Eintrag im Issue „Operator-Inbox", und du trägst ihn nach. Erwartbar betrifft das den Download der Playwright-Browser, sobald das Repository Playwright nutzt; welche Hosts das sind, ist Nicht verifiziert und wird erst gemessen, nicht vorab geraten. **Full** nur als Ausweg, wenn eine Messung zeigt, dass die Liste nicht reicht.
   - Setup script: den Inhalt von `docs/autonomy/cloud-setup.sh` in das Feld „Setup script" kopieren (das Feld nimmt das Skript selbst, keinen Pfad). Das Skript läuft als root, bevor das Repository bekannt ist; es installiert nur Node 24.14.1 (erst nach dem Abgleich mit der `SHASUMS256.txt` von nodejs.org) und ast-grep 0.45.3. `make setup` führen die Lead-Sitzung und die Routine selbst als ersten Befehl aus.
   - Environment variables: leer lassen. `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`, `CLAUDE_CODE_SUBAGENT_MODEL=sonnet`, `BASH_DEFAULT_TIMEOUT_MS=600000` und die Attribution-Schalter kommen aus der committeten `.claude/settings.json`, die `make sync` aus `gates/project.json` rendert (Patch-Punkt 24). Kein `NODE_ENV=production` (die Toolchain braucht die devDependencies), kein `GH_TOKEN` und kein anderes Token: GitHub läuft über den Proxy der Cloud, und Umgebungsvariablen sind für jeden lesbar, der die Umgebung nutzt.
4. **Bootstrap-Patch einspielen** (in deinem eigenen Terminal, nicht in einer Claude-Sitzung: dort sind `make sync`, `make controls-baseline` und `--admin` gesperrt). Die genaue Befehlsfolge steht in `APPLY.md` neben der Patch-Serie. Kurzform: neuer Branch `ops/bootstrap` von `origin/main`, `git am` der Serie, `make setup`, `make sync`, `make controls-baseline`, `make check`, `make gates-selftest`, `make conductor-test`, Commit, Push, PR, `gh pr merge <PR-Nummer> --admin --merge`, danach auf `main` `make doctor`.
   - `make doctor` ist auf `ops/bootstrap` vor dem Merge rot: es vergleicht die Kontrolldateien mit dem Manifest von `origin/main` (`gates/lib/manifest.py`), und dort steht noch der alte Stand. Nach dem Merge und `git pull` muss es grün sein.
   - `protect` ist bei diesem PR erwartbar rot (Kernpfade); genau dafür ist der Bypass aus Schritt 1.
   - Ab dem Merge pushen alle Claude-Sitzungen, auch deine lokalen, nur noch `claude/*` (Regel `BASH-PUSH-MAIN-STATE`); `conductor/state` schreibt nur `ops/conductor/heartbeat.py`. Andere Branches pushst du aus einem Terminal ohne Claude. Ebenso gesperrt sind in Claude-Sitzungen `gh label|run|workflow|variable|secret|repo`-Änderungen (Regel `BASH-GH-MUTATION`) und jedes `gh workflow run` außer `proof.yml`.
5. **Lead-Sitzung starten.** claude.ai/code → Repository `ahlerjam/academic-research`, Branch `main`, Umgebung `academic-research` → aus `docs/autonomy/lead-goal.md` nur den eingezäunten Textblock unter „The message the operator pastes" einfügen (er beginnt mit `/goal`, ohne die Überschrift und ohne die Zeilen mit den drei Backticks) → senden. Den Berechtigungsmodus im Modus-Menü so wählen, dass die Sitzung ohne Rückfragen arbeitet, aber nie „bypassPermissions"; welcher Modus in der Cloud ohne Rückfragen läuft, ist Nicht verifiziert (Phase-B-Smoke-Test).
6. **Stündliche Wächter-Routine anlegen.** claude.ai/code/routines → **New task** → **Set up manually** → Name `ar-watchdog` → Prompt: aus `docs/autonomy/watchdog-routine.md` nur den eingezäunten Textblock unter „Prompt" → Trigger „Schedule", stündlich, ein paar Minuten nach der vollen Stunde (z. B. xx:07) → **Advanced settings** → Repository `ahlerjam/academic-research`, Cloud environment `academic-research` → Reiter „Connectors": alle entfernen → **Create**. `/schedule` geht nur im lokalen CLI, nicht in einer Cloud-Sitzung. Häufiger als stündlich lässt die Routine nicht zu.
7. **Pausieren und zuschauen.**
   - Pause: Label `conductor:pause` am Status-Issue „Conductor status" setzen (geht auch in der GitHub-App; jedes Issue mit diesem Label pausiert, auch ein geschlossenes); die Lead-Sitzung startet dann keine neue Einheit, laufende enden regulär. Weiter: das Label entfernen (Schließen des Issues reicht nicht).
   - Übernahme: Erneuert die Lead-Sitzung ihren Lease eine Stunde lang nicht (etwa nach einer recycelten VM), übernimmt die nächste stündliche Routine; Einheiten, die mitten im Bau hängen geblieben sind, nimmt sie wieder auf.
   - Ganz anhalten: zusätzlich die Routine `ar-watchdog` auf claude.ai/code/routines mit dem Schalter oben ausschalten.
   - Zuschauen: das Status-Issue (Prognose: Einheiten pro Tag, Rest bis zum nächsten Meilenstein und bis v0.1, Stopps durch das Nutzungslimit), das Issue „Operator-Inbox" (Kern-Patches `op:kernel`, nichts davon blockiert), die Sitzungsliste auf claude.ai/code oder im Reiter „Code" der Claude-App, die Läufe der Routine auf claude.ai/code/routines, den Verbrauch auf claude.ai/settings/usage.
   - Der einzige menschliche Punkt bleibt die Anfrage an Anthropic: ein Agent legt den Entwurf als Issue an, abschicken kannst nur du. Sie blockiert nichts.
